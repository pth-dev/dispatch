### E.3 Mobile Behavior Flag (`[OBSERVED]`)

- `Dispatch.html:L6-L30` runs an inline `<script>` at the top of `<head>` before any assets load: if `window.self === window.top` (not embedded in iframe) and `localStorage['dispatch.view'] !== 'desktop'` and `?desktop=once` is not set, any phone UA (excluding iPad/Android tablets) or touch screen with `min(width, height) <= 600` is **immediately redirected via `location.replace('Dispatch-cell.html' + search + hash)`**.
- `Dispatch-cell.html` (WeCom-style mobile UI) is **NOT provided** in `docs/legacy/`.
- `Dispatch.html` itself has minimal responsive Tailwind classes (`md:grid-cols-*`, `lg:grid-cols-3`) and an iframe embed mode (`DU_embedApply`, `Dispatch.html:L1943`) for when `Dispatch-cell.html` embeds desktop pages.

## F. i18n Architecture Facts (Document Only — Open Decision)

### F.1 Legacy Display-Layer Mechanism (`Dispatch-utils.js:L8320-L8785`)

| Aspect | Observed Behavior | Evidence |
|---|---|---|
| **Supported modes** | 4 modes in `DU_LANGS`: `'bi'` (中越双语 / Song ngữ, **default**), `'zhs'` (简体中文), `'zht'` (繁體中文), `'vi'` (Tiếng Việt). **No English (`en`) mode in legacy.** | `Dispatch-utils.js:L8324-L8329, L8363` |
| **Storage key** | `localStorage['dispatch.lang']` (`DU_LANG_KEY`). Shared across all legacy HTML pages. | `Dispatch-utils.js:L8323, L8364, L8770` |
| **How rendering works** | Every string in HTML/JS is hardcoded bilingually (`"中文 / Tiếng Việt"` or `"中文 (Tiếng Việt)"`). On language change (or when overrides exist), `DU_processTree()` walks the entire DOM with `TreeWalker`, splits bilingual strings by `DU_RE_SEP` (`" / "`), keeps the active language segment, and runs a `MutationObserver` (`DU_i18nObserve`) on `document.body` to rewrite dynamically added nodes and `placeholder`/`title`/`alt`/`aria-label` attributes. It also monkey-patches `window.alert`, `confirm`, `prompt` (`DU_wrapDialogs`). Elements with `data-i18n-skip` are excluded. | `Dispatch-utils.js:L8359-L8457, L8695-L8764` |
| **Trad ↔ Simp conversion** | Two character maps + phrase tables: `DU_zhS()` (`L1176-L1193`, Traditional→Simplified for backend messages/dept/type) and `DU_toTrad()` (`L8330-L8346, L8372-L8378`, Simplified→Traditional Taiwan terms for `zht`). | `Dispatch-utils.js:L1176-L1193, L8330-L8378` |
| **Server overrides** | `GET /api/i18n/overrides` (unauthenticated, `cache: 'no-store'`) returns `{ success, version, items: [{ k, zhs, zht, vi, ov }] }`. Cached in `localStorage['dispatch.i18n.ov']`; synced cross-tab via `BroadcastChannel('dispatch-i18n')` + `localStorage['dispatch.i18n.ping']` storage event. | `Dispatch-utils.js:L8460-L8576` |
| **Override key computation** | `k` = Simplified Chinese source text **core** computed by `DU_i18nCore(seg)`: strips leading non-letters (icons/symbols/numbers/spaces) and trailing punctuation (`:：,，.。;；!！?？…、-–—~*`), collapses inner whitespace. Also indexes original Vietnamese `ov` into `DU_ovByVi`. Applied *before* language splitting in `DU_ovLine()`. | `Dispatch-utils.js:L8475-L8530` |
| **Who can edit overrides** | `DU_canEditI18n()` = `admin`, `superadmin`, `exec_assistant`, `exec_vp` (`L8580`). Editor UI lives in missing `Dispatch-language.html` (referenced at `L8468, L8582`). | `Dispatch-utils.js:L8468, L8580-L8582` |

### F.2 Backend-Supplied User-Facing Texts & Conflicts

- **Backend texts (`[OBSERVED]`)**:
  1. API error/status messages (`data.message`, `data.err`) come from `Dispatch.js` in Traditional Chinese or bilingual `"中文 / Tiếng Việt"` format; legacy FE converts them with `DU_zhS(data.message)` (`Dispatch.html:L3776-L3777`; `Dispatch-utils.js:L9858`) and displays them directly in toasts (`showMessage`).
  2. Domain values stored in DB are Traditional Chinese or bilingual strings (`資訊部`, `網路類 / Mạng lưới`, `一般件 (指定时间内完成) / ...`, `無 / Không`, `不顯示 / Không hiển thị`) — these must be sent back to the backend verbatim to avoid splitting statistics (`Dispatch-utils.js:L536, L568`).
- **Conflict 1 — Brief rule "never show raw `error.message`"** (`docs/PROJECT_BRIEF.md:L177, L197`): The brief requires normalizing API errors to a small set of error codes mapped to i18n keys and never showing raw `error.message` in production. However, the legacy backend returns human-readable Chinese/Vietnamese explanations in `data.message` for many business rejections (e.g. AD errors, merge conflicts, duplicate name/username, permission reasons) and only rarely returns a machine `data.code` (only `DUP_TITLE_DUE` is observed in FE).
- **Conflict 2 — Boilerplate localization rule & React** (`.claude/rules/localization.md`, `docs/DEVIATIONS.md:§4`): The new React app uses `i18next` with key-based JSON files (`src/locales/{vi,en,zh-CN,zh-TW}/translation.json`). Legacy server overrides (`/api/i18n/overrides`) are keyed by **Simplified Chinese source text core (`k`)**, NOT i18next keys, and have no `en` column. Mutating React-managed DOM text nodes with a `MutationObserver` would break React reconciliation. (Decision left **OPEN** for the user — see `07-open-questions.md`.)
